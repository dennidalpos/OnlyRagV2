# Critical application audit - 2026-10-01

Assessed checkout: `14ded8d`, initially clean. Scope: product usefulness, code quality, retrieval, ingestion, translation, agent reliability, efficiency, usability and adequate open local models. Hardware recommendations describe product targets, independently of the development machine. No application behavior, settings, models or user data were changed.

## Verdict and evidence boundary

OnlyRag has useful foundations: isolated Electron IPC, enforced process boundaries, local inference, database recovery, versioned edits, checkpoints and application-owned verification. The current product nevertheless has concrete content-integrity defects and insufficient evidence for autonomous coding. Better models alone cannot repair these defects.

The strongest problems are missing/empty document extraction, accepting incomplete LLM normalization, an incomplete hybrid retrieval pipeline, generic embedding truncation and misleading qualification signals. These should take priority over new features.

Evidence categories below:

- **Reproduced**: isolated diagnostic probes against the current implementation. HTTP responses are explicit fixtures where indicated; no real model generations were performed.
- **Source**: directly observed implementation behavior, with consequences inferred from that code.
- **Recorded live**: existing dated evidence in this repository, read in this audit; these campaigns were not repeated.
- **Risk/gap**: a missing verification or a product assessment, not a demonstrated crash or exploit.

This is not a measured speed/quality contest: competitor applications were not run on identical machines and corpora. Their official documentation establishes feature and workflow differences, not superior code quality or universal reliability. Desktop usability findings are based on source; no new visual or assistive-technology session was performed.

## Adequate open local models and hardware targets

These are proposed product baselines to qualify, not certified requirements established by this audit. Parameter count, published context and benchmark scores are not substitutes for successful OnlyRag workflows. CPU offload remains possible where supported but should not be advertised as equivalent responsiveness.

Use explicit model tags, quantization and digest in qualification records. Avoid mutable `latest` tags as a permanent quality guarantee. The Qwen model cards used here specify Apache-2.0; retain the actual distribution notices. All model recommendations are local variants, with no cloud forwarding.

Official Ollama artifacts currently list Qwen3.5 4B/9B/27B at approximately **3.4/6.6/17 GB** and Qwen3-Coder 30B at **19 GB**. These are artifact sizes, not peak VRAM. The coder's 3.3B active parameters reduce compute per token but do not make its total weights a 3.3B memory footprint. [Qwen3.5](https://ollama.com/library/qwen3.5), [Qwen3-Coder](https://ollama.com/library/qwen3-coder), [coder license/model card](https://huggingface.co/Qwen/Qwen3-Coder-30B-A3B-Instruct), [9B model card](https://huggingface.co/Qwen/Qwen3.5-9B).

Ollama's current [context guidance](https://docs.ollama.com/context-length) recommends at least 64,000 tokens for agents, coding tools and web-search workloads, and warns that context increases memory requirements. A 16K agent can be useful on bounded tasks with compaction; it cannot be sold as equivalent repository-scale capacity. OnlyRag should not force a larger window when the actual runtime cannot sustain it.

For embeddings, `qwen3-embedding:0.6b` is approximately 639 MB and supports multilingual retrieval and model-aware dimensional reduction. It is a suitable low-cost candidate, not a drop-in fix for the current generic truncation. `bge-m3` is another multilingual candidate with 1024 native dimensions; correct F05 before recommending it through this application. Existing `nomic-embed-text:v1.5` is small and usable as a baseline with correct prefixes, but its model card is English-oriented; qualify the Italian/mixed-language corpus instead of assuming universal suitability. [Qwen encoder](https://ollama.com/library/qwen3-embedding), [encoder card](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B), [BGE-M3 card](https://huggingface.co/BAAI/bge-m3), [Nomic card](https://huggingface.co/nomic-ai/nomic-embed-text-v1.5).

Ordinary OCR does not require another generative model: keep RapidOCR as the inexpensive primary path. Use the already selected multimodal generator for difficult images only after testing text accuracy and load behavior. A separate moondream download is not a requirement for the core document workflow. A local [Qwen3-Reranker-0.6B](https://huggingface.co/Qwen/Qwen3-Reranker-0.6B) is a candidate for semantic reranking; it is not currently integrated or qualified here, and its peak memory depends on precision/batch/sequence length.

## Recommended change order and acceptance criteria

1. **Protect document content first.** Resolve F01-F03; reject unsupported/empty extraction; preserve originals and incomplete-normalization evidence. Add genuine binary-format fixtures and source-entity/completeness negatives. CSV skipped rows and configured truncation must be visible to users.
2. **Make retrieval and its evidence trustworthy.** Resolve dimension/prefix policy, independent lexical retrieval, claim/source navigation and explicit unavailable-context states. Correct history distances separately. Any persisted-vector change needs backup, readback, rollback and explicit reindexing, not an implicit mutation.
3. **Separate compatibility from qualification.** Replace ambiguous badges, choose task-adequate suites and define effective context/memory requirements. Autonomous coding stays unqualified until its own independent complete tasks pass.
4. **Simplify the path to the first answer.** One general model plus one encoder, primary native OCR, visible document coverage and readable answers. Keep advanced agent/model controls available without requiring every beginner to understand them.
5. **Measure before optimizing more broadly.** Then address indexing, bounded table reads, resource coordination, storage, Python quality gates and package size. Preserve filesystem gates, checkpoints, loop/OOM safeguards and existing budgets/timeouts.

Suggested product acceptance targets, to be agreed and measured rather than claimed as current performance:

- Retrieval Recall@k/MRR and supported-answer citation accuracy on a fixed Italian/English corpus, including exact codes, tables, late-page questions, paraphrases, contradictions and absent answers.
- Complete-source translation comparisons for numbers, names, negations, alternatives, deadlines and delivery conditions; entity preservation alone is insufficient.
- At the declared default model/context: hot first visible output p95 at most about 5 seconds and sustained generation about 15 tokens/second or better on representative tasks; expose cold-start and queue time separately.
- Retrieval p95 around 2 seconds or better on declared corpus sizes; record indexing time, peak RAM/VRAM, cancellation and restart recovery. These are proposed UX thresholds, not results or universal model specifications.
- Independent agent acceptance over complete tasks, with frozen tests and rendered-app checks. Repeat bounded sequences and interruption/resume cases; record failures as failures without increasing application retry budgets to conceal them.
