## Proposed release scope

Treat the distributed OnlyRag application, including Electron and the Python Sidecar using PyMuPDF/MuPDF, as a covered combined work for delivery under GNU AGPL v3. Publish its complete corresponding source. Preserve original MIT permissions/copyright for project source and all component-specific grants; do not replace Apache, BSD, OFL or data licenses with AGPL. Confirm upstream version-option wording before final release declarations. This scope avoids depending on an unproved claim that local HTTP or separate processes make the application mere aggregation.

**Approved and implemented packaging change:** use an isolated CPU-only Sidecar release environment with `onnxruntime==1.29.0`, without `onnxruntime-gpu` or NVIDIA packages. Native OCR remains available through the CPU provider; packaged operation and performance must be qualified. The exact CPython 3.13 Windows x64 CPU wheel exists in the [official release metadata](https://pypi.org/pypi/onnxruntime/1.29.0/json), with its URL/hash recorded in the evidence report; the isolated build environment now uses that CPU release. The development GPU environment and external Ollama GPU acceleration are outside this packaging change. Keep one standard installer initially; optional GPU installers would require a separate review.

This changes the shipped OCR acceleration capability. Existing CPU fallback in the GPU wheel does not remove its GPU libraries. The owner approved this capability change before dependency/build edits. Development GPU requirements remain separate; no version downgrade was performed.

## Why the current GPU bundle needs a separate decision

Twenty retained NVIDIA DLLs match installed-distribution bytes: cuBLAS 13.7.0.27, NVRTC 13.4.59, CUDA runtime 13.4.49, cuDNN 9.26.0.51, cuFFT 12.4.0.34, cuRAND 10.4.4.49 and nvJitLink 13.4.52. Their total is **1,643,360,448 bytes** (about 1.53 GiB), excluding five matched ONNX Runtime GPU native files totaling 209,445,992 bytes. This is selected file size, not a measured installer reduction. Installed RECORD hashes/terms and frozen hashes are retained; independent upstream wheel/build provenance is still incomplete.

[CUDA terms](https://docs.nvidia.com/cuda/eula/index.html) require matching redistribution conditions and restrict imposing specified open-source obligations on the SDK. [Current cuDNN terms](https://docs.nvidia.com/deeplearning/cudnn/backend/latest/reference/eula.html) contain related restrictions. Applicability of separate grants, aggregation or System Libraries needs component-specific evidence; dynamic loading and separate processes do not establish it by themselves. No categorical infringement finding is made here.

The installed cuDNN package's license supplement is dated January 28, 2020 and names `cudnn64_7.dll`; the retained package contains cuDNN 9 DLLs. Its exact license hash is in the report. The current web supplement names runtime DLLs more generally, but does not establish which terms accompany those exact files. Retaining GPU packaging would keep this rights/provenance review as a release blocker. CPU packaging removes this particular redistribution surface; it does not resolve all remaining component obligations.

## Source and notice delivery

The [verbatim AGPL text](./licenses/agpl-route-2026-10-10/AGPL-3.0.txt) is retained from the official Artifex MuPDF repository at an immutable `COPYING` revision, with URL and SHA-256. GNU's direct endpoint timed out during the final retention attempt; this retained file is not claimed to be that endpoint's exact bytes or the source revision of the bundled MuPDF. [PyMuPDF's current license documentation](https://pymupdf.readthedocs.io/en/latest/about.html#license-and-copyright) confirms the AGPL/commercial routes.

| AGPL requirement | Concrete proposed delivery |
| --- | --- |
| Sections 0, 4 and 5: copyright, grant, changes, warranty and applicable interactive notices | Preserve component notices; provide a prominent About/licenses entry showing the release grant, no-warranty statement, redistribution rights and accessible full terms. Preserve original copyrights and dated modification notices. |
| Sections 1 and 6(d): corresponding source accompanying downloadable object code | Offer `OnlyRag-<version>-source.zip` next to the installer with equivalent access at no additional charge, and explicit directions. Bind both to one release manifest with SHA-256 and source/build revisions. A moving repository branch or current source Sidecar folder alone is insufficient. Maintain availability for the period required by this delivery method; do not substitute an unsupported written-offer route. |
| Section 1: preferred source and build/install/run scripts, including required linked components | Include project sources, schemas/resources, exact locks/constraints, packaging scripts, patches and dependency source archives/revisions needed to build the covered work. Bind actual PyMuPDF and MuPDF versions/native build settings, not just a PyMuPDF tag. Document any System Library/tool exclusion with evidence. Include native dependency source where required and exact third-party notices. |
| Section 6: Installation Information where its User Product conditions apply | Evaluate the actual distribution transaction; provide required installation information if applicable, without imposing a new signing or activation restriction. Existing unsigned policy remains. |
| Sections 10 and 12: downstream rights and conflicting obligations | Do not add an EULA that removes AGPL rights. Resolve third-party restrictions before shipping; a notice cannot grant absent rights. |
| Section 13: modified work supporting remote network interaction | If applicable, offer corresponding source prominently to all remote users at no charge. Current local/authenticated operation is not a general exemption for a future remotely exposed modified service. Review the actual exposed surface; do not change network access in this task. |

Proposed installed resources: a single `resources/licenses/` directory containing full terms, component notices and a release-specific source-delivery manifest. Wire it explicitly into Electron resources and Sidecar collection. Generate notices from the final artifact's actual component inventory, including Renderer/Main code and native libraries. The approved resources directory is included in fresh CPU candidates; original retained installers are unchanged.
