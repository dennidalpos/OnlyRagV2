# Renderer React

## Claim/source navigation — 2026-10-02

Chat assigns `[S1]`-style references only to passages actually supplied after context truncation. On completed generation, unknown references are reported and sources separate model-cited passages from uncited candidates. Streaming, stopped and failed responses do not promote citations. Clicking an eligible reference/card opens a fresh revision/identity-checked original location; stale/deleted/missing originals show an explicit error. Known PDF pages display the retained original PNG plus the exact extraction excerpt. Legacy or ambiguously rewritten/repeated passages have no verified original-span link. Location verification is labeled separately from semantic support. Optional citation fields round-trip through existing chat storage; no personal conversation migration. [Policy](./rag-sidecar.md#claimsource-provenance--2026-10-02), [verification](./verification.md#claimsource-provenance--2026-10-02).

## Retrieval scores — 2026-10-02

Chat source cards display a decimal ranking score, with an IT/EN explanation that it is a heuristic rather than evidence confidence. Cards are labeled retrieved passages: the selection does not prove they support an answer claim. The prior percentage/relevance label and its unused translations are removed. Sources and scores remain backward compatible in saved messages; no history migration is introduced. The existing document prompt requires explicit abstention when supplied text does not support the answer, without treating zero term overlap as grounds for rejection. DOM checks cover both languages and preserve unrelated and cross-language passages. Model-specific reviewed outcomes and open language/provenance/desktop limits: [RAG policy](./rag-sidecar.md#ranking-scores-and-insufficient-evidence--2026-10-02), [verification](./verification.md#ranking-score-presentation-and-evidence-policy--2026-10-02).

## Salvataggio delle impostazioni — 2026-10-02

`SETTINGS-PERSISTENCE-FEEDBACK-01` e completato. Il banner globale distingue salvataggio in corso, conferma del Main e modifiche non salvate; un errore mantiene i valori in memoria e offre Riprova. I messaggi IT/EN usano `role=status` o `role=alert`, senza spostare il focus. La conferma vale solo per l'ultimo snapshot: completamenti obsoleti non confermano nuove modifiche. Il debounce resta 100 ms e le scritture restano serializzate; snapshot superati ancora in coda non vengono scritti. Un caricamento fallito continua a bloccare salvataggi e diagnostica.

DOM e readback del repository passano; Electron prova un errore reale del writer su un profilo temporaneo, retry dei valori correnti e reload del file salvato. La chiusura prima del debounce o con scritture pendenti resta in `SETTINGS-CLOSE-DURABILITY-01`. Fonti rilette il 2026-10-02: [ciclo di vita degli effetti React](https://react.dev/reference/react/useEffect), [messaggi di stato W3C](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html). Evidenze: [verification](./verification.md).

La chat verifica elenco e contenuto aggiornati dei documenti selezionati prima di generare: una selezione eliminata resta riconoscibile, non diventa una chat senza allegati; nel pannello Contesto è deselezionabile anche se non compare più nell'elenco. Ricerca fallita, elenco indisponibile, contenuto indisponibile o testo vuoto interrompono la risposta con motivi e conteggio dei documenti caricati. Un caricamento parziale non avvia Ollama né espone candidati come fonti della risposta. Gli estratti limitati dal budget sono segnalati nel messaggio e nel prompt; solo un testo completo che rientra nel budget usa `Full Document`. La cache Markdown degli altri consumatori resta indipendente.

Ogni invio chat assegna un'identità prima della ricerca e la conserva per caricamento, coda Ollama, stream e salvataggio nella conversazione d'origine. Stop, cambio/nuova chat ed eliminazione invalidano subito la run e salvano il testo ricevuto con un avviso di risposta incompleta; la conferma asincrona della cancellazione non modifica una run successiva. Il cleanup al dismount impedisce nuove generazioni e callback tardivi. Le letture Sidecar già inviate possono terminare entro i timeout esistenti, ma il loro risultato è ignorato. La durata di un turno ancora attivo alla chiusura non è qualificata; resta in `CHAT-DURABLE-HISTORY-01`.

Un risultato fallito di `ingest:file` con `normalizationReview` apre il pannello [`NormalizationReviewPanel.tsx`](../src/components/ingestion/NormalizationReviewPanel.tsx): motivi localizzati, originale completo di sola lettura ed export Markdown. Il testo rimane una bozza in memoria, senza documento/chunk o ripristino dopo riavvio. La selezione corrente e le modifiche dell'editor restano indipendenti; la normalizzazione non viene abilitata automaticamente.

Il Renderer in `src/` usa React 19, Vite, Tailwind CSS e Monaco. Lo stato è gestito localmente dagli hook React; non usa Zustand.

## Hook e servizi

Document editor ownership (2026-10-06): delayed saves update the saved document's cache/list without switching the current selection. Later edits remain dirty against the confirmed saved text. Dirty navigation retains per-document drafts for the mounted Ingestion view, including when a save fails; an acknowledged deletion removes that document's draft. Ctrl+S/Cmd+S runs only while Ingestion is active. Save status and its timer belong to the originating selection, and duplicate saves are blocked synchronously. Drafts are not persisted or restored after unmount/crash; durability and retained-draft memory limits remain in `DOC-EDITOR-DRAFT-DURABILITY-01`. [Verification](./verification.md#document-editor-ownership--2026-10-06).

Markdown translation ownership (2026-10-06): a job claims the shared translation slot and module lock before loading content. Stop and Reset invalidate it before awaiting cancellation; old tokens, errors and completion cannot update or unlock a later job. Unmount cancels the owned stream; pending document reads settle within existing limits without dispatching another generation. Changing the source revision, language pair or page scope clears the output and cancels the old job. Only output completed for the current source/scope/languages is exportable; stopped/failed partial text is labeled incomplete. Export feedback also ignores settlements after Reset or a new job. PDF/DOCX Sidecar cancellation after unmount remains in `TRANSLATION-INPLACE-UNMOUNT-CANCELLATION-01`; this correction does not qualify semantic fidelity. [Verification](./verification.md#translation-operation-ownership--2026-10-06).

- `useCodingAgent` compone gli hook in [`hooks/codingAgent/`](../src/hooks/codingAgent/): `useAgentActionLog` (timeline), `useCodingAgentExecution` (run, eventi IPC legati all'identità della run, coda, conferme), `useCodingAgentSession` (cambio, creazione ed eliminazione delle conversazioni, persistenza), `useCodingAgentAttachments` (documenti RAG allegati) e `useCodingAgentTerminal`. L'effetto IPC legge lo stato corrente tramite ref, quindi un prompt avviato dalla coda usa modalità, conversazione, editor e allegati aggiornati. `CodingAgentLeftPanel` e `CodingEditorContent` ricevono solo i campi dichiarati nei loro tipi `…Model`.
- `useChatEngine`: conversazioni, retrieval, routing di dominio, budget e streaming.
- `useIngestion` e `useTranslation`: flussi Sidecar e progress eventi. `useDocumentTranslation` (Markdown) e `useInplaceTranslation` (PDF/DOCX con layout) hanno selezioni documento indipendenti; condividono lingue, lock tra moduli e risoluzione di modello/contesto/thinking. Senza modello di traduzione o predefinito entrambe mostrano un errore invece di usare un modello di ripiego. `TranslationView` monta entrambi gli hook e possiede la coppia di lingue e il job attivo (`useSharedTranslationState`): la prenotazione sincrona consente un solo job alla volta, incluso il caricamento Markdown. Lo stato del job in-place (progresso, lock `translation`) sopravvive al passaggio alla scheda Markdown finché il job del Sidecar è in corso, e il pannello offre **Annulla**, che chiama `task:cancel` con il `taskId` degli eventi `ingest:translate-progress` e mostra l'esito annullato.
- `useIngestedDocuments` riceve solo metadati. Il Markdown di un documento si carica su richiesta con [`documentMarkdown.ts`](../src/services/documentMarkdown.ts) (`loadDocumentMarkdown`, cache limitata per ID e `ingestedAt`, quindi un documento salvato non viene servito dalla versione precedente) o con l'hook `useDocumentMarkdown`: editor di Ingestion, traduttore Markdown, contesto della chat e allegati del Coding Agent. L'editor parte vuoto salvo bozza locale e non e salvabile finché il testo del documento selezionato non è arrivato; anche il testo digitato durante il caricamento e conservato. Le modifiche non salvate sopravvivono a un aggiornamento della lista; una bozza gia salvata non copre una nuova revisione esterna.
- `useSessionHistory` e `useWorkspaceProjects`: persistenza del Coding Agent nel Main (`sessions:*`, `projects:*`); per questi flussi localStorage conserva preferenze di interfaccia (tab attiva, ultimo workspace, larghezze dei pannelli). La cronologia della chat documentale usa ancora localStorage, come descritto sotto.

Project registry integrity (2026-10-06): project names, registration and removal reflect acknowledged Main writes and an authoritative reload. Failed/null/false results preserve the confirmed list and show the existing registry warning/retry; unrelated successful operations cannot clear a refusal warning before retry. Older list responses cannot undo a newer mutation, and delayed removal cannot reverse a newer workspace selection. Cached conversations and active-view cleanup wait for confirmed unregistering; project files and `.onlyrag` remain intact. Selecting a workspace remains immediate, including when saving its registry entry fails. Standalone scratch responses update the path only for the current mounted selection; older startup/toggle/removal responses and StrictMode cleanup cannot reverse a project choice or a newer standalone request. [Registry verification](./verification.md#project-registry-mutation-integrity--2026-10-06) and [selection verification](./verification.md#standalone-workspace-selection--2026-10-06).

Dal 2026-10-06 un errore di lettura non crea una nuova cronologia vuota: Main rifiuta le mutazioni dipendenti, preservando l'archivio illeggibile. Coding Agent mostra un avviso localizzato e un pulsante di retry. Le scritture di sessione rifiutate restano in memoria e vengono ritentate prima del reload; una cancellazione confermata elimina il relativo retry. Tieni aperta la vista finché il salvataggio non riesce: recupero durevole dopo chiusura/crash, acknowledgement delle scritture agente e conferme di cancellazione hanno task separati. Lo stato agente illeggibile blocca letture dipendenti, ripresa e scritture; il controllo e completato, con [evidenze dedicate](./verification.md#agent-state-preservation--2026-10-06). Formati e compatibilità legacy restano invariati. [Evidenze e limiti sessioni](./verification.md#session-store-preservation--2026-10-06).

Workspace unregister preservation (2026-10-10): removing a project registry entry clears its visible history cache, but retains failed owned snapshots and pending debounced writes. Retry Storage persists the original session/workspace identity even after switching projects. Confirmed durable session deletion keeps its existing retry removal; closing/crashing with unsaved snapshots remains unqualified. [Focused verification](./verification.md#workspace-unregister-preserves-failed-session-writes--2026-10-10).
- `hardwareRecommendationEngine`, `domainRouter`: compatibilità modelli, capacità e routing.
- `chatContextBudget` e `chatContextCompactor`: budget e riduzione della cronologia.

Directory chooser ownership (2026-10-06): only the latest chooser in the current mounted selection can select its returned folder. Newer explicit selections, later choosers and unmount invalidate earlier results; cancelling a chooser does not change the selection. Native dialog failures are logged. [Verification](./verification.md#workspace-directory-chooser--2026-10-06).

Session deletion progress (2026-10-06): false/rejected/missing Main acknowledgements keep the conversation and unsaved snapshot visible. Confirmed active deletion hydrates the replacement and clears attachments only for the owned view. Main cleanup failures require retrying Delete while keeping the view open; the generic storage reload is not a deletion retry. Restart recovery, concurrent writes and changed-history-view handling remain open in `SESSION-DELETION-ACKNOWLEDGEMENT-01`. ## Componenti tecnici

- `AgentTimeline` usa `@tanstack/react-virtual` per ridurre il costo del rendering dei log.
- `monacoTheme.ts` centralizza tema e opzioni Monaco.
- Il bundle iniziale non pre-carica Monaco o il tokenizer. L'editor Markdown di Ingestion viene caricato solo quando si apre un documento; Monaco e tokenizer delle altre viste arrivano quando si apre la rispettiva interfaccia.
- I testi dell'interfaccia vivono in [`src/i18n/locales`](../src/i18n/locales/) (`it`, `en`, stessa struttura di `types.ts`). I componenti e gli hook usano `useTranslation().t`; il codice fuori da React (normalizzatore errori, servizi, azioni rapide) usa `translate()` di [`I18nContext.tsx`](../src/i18n/I18nContext.tsx), che segue la lingua del provider montato (italiano se non c'è). Il progresso dell'ingestion arriva dal Sidecar come `step_code`/`step_params` e viene tradotto da `sidecarStepText` (`ingestionSteps.*`), con il testo inglese `step` come ripiego. Sessioni di coding e conversazioni chat senza nome hanno titolo vuoto (`''`): la vista mostra il predefinito della lingua corrente (`coding.sessionTitleDefault`, `chat.newChat`). Un titolo salvato non vuoto è sempre un nome scelto dall'utente. Le voci della timeline dell'agente prodotte in Main possono portare `localized` (chiavi di messaggio con parametri, anche annidati, e righe testuali verbatim; [`agentMainText.ts`](../shared/domain/agent/agentMainText.ts)): `localizeAgentLog` le mostra nella lingua corrente (`agentMain.*`), mentre `message`/`detail` restano il testo italiano di ripiego, lo stesso che legge il modello. I template italiani vivono solo in `AGENT_MAIN_TEXT_IT`, che la locale `it` riusa. Sono migrati il riepilogo di chiusura applicativa, il motivo di chiusura (`ApplicationClosureRequest.reason` è un `AgentLocalizedText` con chiavi `reason*`, prodotte anche dal dominio: `schemaStopReason`, `AgentProgressPolicy.onStepExecuted`) e la voce «Diagnostica sessione» (`diagnostic*`). In Main `emitLocalizedLog` ([`agentOrchestratorTypes.ts`](../electron/core/application/agentOrchestratorTypes.ts)) emette una voce da chiave e parametri; la usano i messaggi di milestone, piano, loop e circuit breaker di `agentOrchestratorToolResultProcessor.ts`, `agentOrchestratorCircuitBreakerAndVerification.ts`, `agentOrchestratorAskAutoHealing.ts`, `agentOrchestratorFinishAndLoopGuards.ts`, `agentOrchestratorToolGates.ts` e `agentOrchestratorTurnDispatch.ts`. Il Renderer che deve reagire a una voce ne legge la chiave, non il testo (il suono d'errore di `useCodingAgentExecution.ts` usa `circuitBreakerTriggered` e `llmStreamError`). Il Renderer riconosce alcune voci dal testo mostrato (`❓ AI Agent Question:`, `Task Finished:`, `Consulting LLM (<modello>)`, `Loop` nei banner di loop): quelle restano con prefisso fisso e i template di loop mantengono la parola «Loop» in entrambe le lingue. Il `summary` di `agent:done` resta il testo italiano: la UI non lo mostra, lo salva nel prompt eseguito e lo indicizza per la ricerca nella cronologia.
- I risultati di `run_command` e `run_tests` forniscono una chiave strutturata nel campo `ToolExecutionResult.localized.message`; la timeline la mostra nella lingua corrente. L'output dei comandi resta verbatim nel dettaglio, mentre il messaggio di ripiego è in italiano.
- Monaco include solo i linguaggi aperti dall'app (`markdown`, `typescript`, `javascript`, `css`, `html`, `python` con evidenziazione Monarch) e il solo servizio di linguaggio JSON: il plugin `monacoLanguageSubset` di [`vite.config.mts`](../vite.config.mts) risolve gli altri a un modulo vuoto, quindi il build non contiene più i worker TypeScript (6,9 MB), CSS e HTML. Per aggiungere un linguaggio all'editor va aggiunto a `MONACO_LANGUAGES`.
- La chat rende ogni messaggio con `ChatMessageItem` memoizzato: il flush dello streaming ogni 40 ms sostituisce solo il messaggio in crescita. Il drawer diagnostico ignora i poll che non cambiano il buffer dei log e usa chiavi stabili per riga; il conteggio token dell'editor dei prompt è debounced (250 ms) e la cache di `tokenEstimate.ts` è limitata a 200 voci e 2 milioni di caratteri.
- Nel Coding Agent la larghezza del pannello sinistro si adatta allo spazio disponibile e lascia visibile l'editor anche a 1024×700.
- `errorNormalizer.ts` converte errori tecnici in messaggi e remediation UI.
- Le chiamate al Main passano da `window.electronAPI`; non si accede direttamente a Node o al filesystem.
- Drag/drop e input HTML risolvono il `File` selezionato tramite il bridge locale Preload `resolveNativeFilePath({ file })`. File senza origine su disco ed errori di risoluzione mostrano un errore tradotto, senza avviare ingestion; nessun fallback al nome del file o a `File.path`. Il dialogo nativo mantiene il percorso completo. [Contratto e verifica](./api-ipc.md#native-upload-bridge--2026-10-06).
- `settings.json` sotto `userData` è la fonte canonica delle impostazioni, nel solo formato versionato `{ version: 2, settings }`; se il file manca l'app parte dai valori predefiniti. La diagnostica parte dopo il caricamento; la scelta automatica di un modello si applica solo se `defaultModel` è ancora vuoto. Se `settings:get` fallisce (per esempio `settings.json` illeggibile, senza versione o con versione non supportata) `AppLayout` mostra un avviso con «Riprova»: finché il caricamento non riesce non salva, non apre il wizard e non avvia la diagnostica automatica, quindi il file resta intatto. Main legge le impostazioni per uso interno con fallback ai valori predefiniti.
- La RAM di sistema è mostrata con valori distinti per memoria disponibile, in uso e totale sia nella barra laterale sia nella diagnostica; il report copiabile mantiene le stesse etichette.

La persistenza chat e separata in `useChatHistory` e `chatHistoryStorage`: schema validato, formato e campi aggiuntivi conservati, scritture accorpate e avviso persistente con Riprova. Una cronologia illeggibile blocca le scritture per preservare i dati originali; i messaggi nuovi restano in memoria. La quota esaurita mantiene i messaggi e l'ultima cronologia salvata.

## Model/workload fit — 2026-10-02

Wizard options and context controls show the effective window, estimated memory range or observed allocation, and GPU/CPU/offload/unknown placement. Coding shares its unchanged agent context default with execution; existing setup confirmation preserves context overrides. Local memory cannot qualify remote endpoints. Estimates expose unknown cache/parallel settings, and memory labels do not imply task quality or speed. No automatic setting change or admission relaxation. [Policy and evidence](./model-runtime-fit.md).

## Modal focus and accessibility — 2026-10-02

The shared `Modal` uses one priority stack for base, nested and approval layers. Opening focuses the panel, Tab/Shift+Tab remain within eligible controls (including radio groups), and empty panels retain focus. Only the active layer handles Escape/backdrop; nondismissible approval dialogs require explicit Approve/Reject buttons. Closing restores the previous eligible trigger or parent panel, including when a parent unmounts first. Callback changes do not reset focus. Existing body-scroll reference counting remains in use.

Background body children and lower dialogs are inert while the active dialog is open; dynamically inserted children are included. Cleanup restores the original inert attributes, including pre-existing inert content. Duplicate approval Escape handlers were removed. Keyboard and native Chrome accessibility-tree verification uses actual production components; real screen-reader, zoom and restarted Electron/Monaco interaction qualification remains in `MODAL-ASSISTIVE-TECHNOLOGY-QUALIFICATION-01`. [Commands and evidence](./verification.md#modal-focus-and-accessibility--2026-10-02).
