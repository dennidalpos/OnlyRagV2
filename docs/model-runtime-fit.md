# Model/runtime fit

## Boundary proposal — 2026-10-02

Status: approved by the user and implemented on 2026-10-02; `MODEL-RUNTIME-FIT-01` is complete. The six-file baseline passes 62 tests in 1.78s. The replaced estimator assumed 32 layers, 8 KV heads, 128-dimensional heads and Q8 cache for every model; wizard options used 4096 tokens even when setup chose a larger window. GPU-only rejection also omitted possible CPU offload. Historical tests verified that implementation, not actual memory fit.

Proposed additive boundary: keep `ollama:get-model-metrics` and its request unchanged, adding optional validated fields to `OllamaModelMetrics`:

- `memoryGeometry`: architecture, block count, embedding length, attention/KV head count and key/value lengths from `/api/show`. Retain only bounded scalar metadata needed for estimation; never copy tokenizer arrays or raw model templates. A recognized conventional full-attention layout may yield a KV estimate; hybrid/recurrent/sliding/shared-KV/unknown layouts remain explicitly uncertain until supported or observed.
- `runtimeAllocation`: timestamp, digest, total bytes, GPU bytes and loaded context from `/api/ps`, bound to the same installed model identity. Missing or mismatched measurements remain unavailable. Loaded context is an observation, not a new trained ceiling or proof that a different requested workload fits.

These are optional transient facts, not new saved settings, Sidecar REST fields or database schema. Existing consumers retain their fields. Keep current local inference boundaries and five-second metadata-query timeouts; do not start generation, install/unload models, read credentials or alter Ollama configuration during probing.

Proposed behavior:

1. Prefer the actual installed weight size and quantization over a name-based catalog estimate. A size from `/api/tags` is a storage weight estimate, not observed runtime allocation. Show which basis is available.
2. Use the effective context selected by the existing role-specific resolver, saved override and trained ceiling. Setup, model selectors and execution assessments use the same workload/context inputs. Preserve existing context caps, reserves, OOM checks and app retry/time limits; no automatic enlargement or settings write.
3. Never infer KV-cache quantization from model-weight quantization. Unknown server cache/parallel/batch configuration produces an explicit range or unknown result, with assumptions visible. No assumed Q8 default. Fresh compatible `/api/ps` allocation may supplement the estimate only for its recorded context/digest; it cannot certify unseen concurrency or extrapolate hybrid memory geometry.
4. Distinguish GPU-resident fit, possible CPU/offloaded fit, insufficient memory and unknown. Use existing RAM/VRAM safety reserves. CPU availability does not prove acceptable speed, supported acceleration or safe simultaneous workloads. Missing remote-host hardware means unknown; local-PC memory cannot certify a remote endpoint.
5. Replace misleading fixed-4K badges with effective context, memory basis/range and placement uncertainty. Fit remains separate from task quality and latency qualification. Existing admission safeguards remain enforced regardless of informational fit labels.

Verification after approval: capture authoritative fields from the installed local endpoint without inference; use native HTTP/domain/DOM checks for different attention geometries, Q4/Q8/F16 model weights versus independently configured cache, missing/malformed metadata, identity/context mismatch, CPU-only/offload hosts, remote unknown hardware and effective-context agreement. Update affected documentation and remove the task only after these acceptance paths pass. Any unsupported architecture, broad allocation/latency campaign or shared admission work stays separately tracked.

Sources checked 2026-10-02: [Ollama show](https://docs.ollama.com/api-reference/show-model-details), [loaded-model allocation](https://docs.ollama.com/api/ps), [runtime context/cache/parallel configuration](https://docs.ollama.com/faq). The proposed estimator policy is an application decision, not a universal memory guarantee.

## Implemented policy and verification

Main enriches the existing model-metrics result with scalar geometry and a digest-bound `/api/ps` allocation observed at receipt. Installed weight bytes/quantization remain distinct from runtime bytes. Show and runtime probes run together within their existing five-second timeouts. Only conventional `llama`, `qwen2` and `qwen3` full-attention geometry is estimated; explicit sliding/shared/recurrent metadata, other architectures and encoder-only capabilities stay unsupported. Missing KV-head metadata is not invented. Cache range is Q4_0 through F16 for one sequence; block sizes follow [GGML's declarations](https://github.com/ggml-org/llama.cpp/blob/master/ggml/src/ggml-common.h). The existing 0.25 GiB runtime allowance and RAM/VRAM reserves remain estimates; batch/parallel/model overlap needs measurement.

Observations are used only for the same digest/context and within 60 seconds; malformed splits, stale/mismatched evidence and unknown accelerator hardware cannot certify fit. They describe the recorded allocation, not speed or simultaneous request safety. Remote/non-loopback endpoint assessments never use local-PC memory, even if a saved mode says local. Conventional estimates distinguish possible GPU residency, possible CPU/offload placement, insufficient combined memory and unknown. A split that may fit combined memory but lacks loading/transient evidence remains unknown. No positive memory label admits a request or overrides safeguards.

Wizard labels use the context that its existing confirmation would save, with current overrides and trained ceilings. Settings labels assess their displayed effective window; coding shares the unchanged agent default policy with execution. Agent preflight records the same assessment at the actual effective run context as an informational, nonblocking check; existing blocking context/tool/workspace checks stay enforced. Old fixed-geometry functions and misleading VRAM-only translations were removed. No settings were changed automatically.
