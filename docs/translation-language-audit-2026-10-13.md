## Source-confirmed defects and priorities

1. **P1 - immutable email protection.** `_mask_immutable_entities` substitutes company names before email addresses. A company name matching an email domain becomes a placeholder inside that domain; the full-email regex can no longer match it. The model can therefore translate the exposed local part while retaining all known placeholders, and validation still accepts it. Actual Spanish evidence demonstrates both changed contacts. A native offline synthetic probe reproduces the defect using `Example S.p.A.` and dummy `first@example.com` / `second@pec.example.com`; no further model call is made. Remediation must protect complete contacts atomically and preserve existing strict marker/identifier refusal.
2. **P1 - complete translation fidelity.** Mixed/wrong target language, changed literal addresses/places, invented field/product meanings, ambiguous postal terminology and unfaithful clauses remain in complete outputs. These belong to the existing translation-fidelity task; successful export/readback does not close it. Check every source/output clause and target language rather than certifying a transport/content-presence result.
3. **P2 - legitimate unchanged labels.** `_validated_translation` rejects every unchanged source label containing an asterisk. Italian/Portuguese `NOME` demonstrates a legitimate cognate that passes marker preservation but is still rejected. A native synthetic probe reproduces it. The existing translation-marker task retains this residue; allowing arbitrary unchanged labels or weakening marker checks is not an approved fix.
